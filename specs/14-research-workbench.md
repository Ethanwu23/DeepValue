# DV-14 研究工作台

状态：Accepted（随本 PR 合并到 dev 生效）；版本：1.0；日期：2026-10-25。
关联：[Issue #16](https://github.com/Ethanwu23/DeepValue/issues/16)。公共约束：[总规约](00-system-contract.md)。本文件定义目标行为，不宣称已实现。

## 1. 目标与范围

保留当前工作台样式，拆表单、运行状态、财务、证据、报告与审查视图。

非目标：登录、多租户、实时行情盘、交易操作、旧聊天界面兼容。

## 2. 现状、复用与变更

现有实现（相对 backend/src/agent，前端及根目录文件除外）：frontend/src/App.tsx、lib/api.ts；components/ChatMessagesView.tsx。

从 App 抽业务 hooks 与视图；复用 Markdown 组件并移除未使用旧聊天入口。

迁移必须先复制对应实现到目标模块再改写；新增能力没有既有实现时明确新增，不复制不相关代码。

## 3. 输入与输出

- 输入：模型与能力配置、请求输入、RunEvent、ResearchResult。
- 输出：研究提交/取消操作、结果视图、同 run 的导出。
- 依赖：DV-01、DV-12、DV-13、DV-15。
- 数据字段、状态、日期和预算使用总规约，不自定义同义字段或隐式空成功。

## 4. 行为规则

1. 提交前校验格式与 PE；服务端为最终校验来源。显示支持行业、估值方法、宏观配置状态及当前功能边界。
2. 请求提交冻结 activeScope；新 run 一开始清空旧报告、财务、证据与下载入口，不等服务器首个事件。
3. 运行状态、研究完整性、估值状态分开展示。事件按 seq 排序、event_id 去重，忽略不同 run 的晚到数据。
4. 运行中冻结表单；停止按钮显示 cancelling，等待后端 cancelled 确认；仅断开流时显示连接中断，不能宣称取消成功。
5. 报告/财务/证据/审查/执行记录分别展示；对拒绝来源、未解 gap 和模型失败有明确入口，不以绿色完成掩盖缺口。
6. 导出使用后端冻结 ExportBundle，不直接 JSON.stringify 整个 LangGraph 内部 state；文件名由结果标的与截止日生成。
7. 模型列表配置失败显示错误并禁用提交，不植入硬编码模型；服务重启导致 run 丢失时显示失效。
8. 移动端可访问；表单标签、按钮状态、错误提示、键盘操作和表格滚动必须可用。

## 5. 失败、预算与安全

使用总规约 ErrorInfo 和全局 BudgetLedger；外部请求仅经 DV-15，实际发出前预留预算。业务缺口与系统异常分开，不以默认值、空对象、备用模型或备用来源掩盖错误。取消和终态优先级由 DV-13 统一控制，纯计算能力也不得提交已取消运行的结果。

本能力的特殊失败行为已在上面的规则与下面的场景中规定；不可恢复的供应商协议错误进入缺口，内部不变量错误由运行时标记 failed。

前端使用总规约9.1中的统一API与SSE事件，迁移时移除直接useStream提交内部图state的路径。连接中断可按seq重连；404显示运行失效，409按错误码提示已有活跃研究或结果未就绪。

## 6. 验收场景

| 编号 | 场景 | Given | When | Then |
|---|---|---|---|---|
| DV-14-AC-01 | 新请求隔离 | 已显示上一轮报告 | 提交新请求 | 立即清空旧结果并禁止旧导出 |
| DV-14-AC-02 | 状态分离 | completed+limited+calculated | 展示 | 同时显示研究结束、有限结论和已计算情景 |
| DV-14-AC-03 | 取消未确认 | 只断开事件流 | 操作停止 | 不能显示后端已取消 |
| DV-14-AC-04 | 晚到事件 | 旧 run 事件晚于新请求 | 更新 | 忽略旧run事件；同run按seq去重重连，不重复展示 |
| DV-14-AC-05 | 配置失败 | 模型列表接口错误 | 打开页面 | 显示错误且不能提交 |
| DV-14-AC-06 | 导出正确 | 表单已编辑但结果属于上次 run | 导出 | 内容与文件名均对应冻结结果；非completed导出409 RESULT_NOT_READY |
| DV-14-AC-07 | 可访问性 | 键盘及窄屏浏览 | 提交和切换结果 | 标签可识别、焦点可用、表格不遮挡操作 |

## 7. 实现及特征测试映射

- 目标实现：frontend/src/features/research/、contracts/、components/markdown/。
- 计划测试：`frontend/tests/research-workbench.spec.ts`；使用浏览器验证交互，不用 Python 模拟 UI。
- 测试方法：固定输入和脱敏来源样本验证上述编号；涉及供应商的协议检查与真实接入验收分离；模型审查以固定合法/不合法输出验证路由和约束，不要求实时模型逐字相同。
- 当前阶段仅定义场景，不创建测试脚本。目标路径为计划，须与迁移矩阵一起随实现更新。
